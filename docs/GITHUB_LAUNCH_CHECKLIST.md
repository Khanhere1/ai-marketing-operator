# GitHub Public Launch Checklist

## Before publishing

- Confirm project name, trademark position, and repository ownership.
- Select and add the final open-source license after legal review.
- Add maintainer and security contacts.
- Enable branch protection, signed releases, secret scanning, dependency updates, code scanning, and private vulnerability reporting where available.
- Remove secrets, customer data, internal URLs, credentials, and confidential examples.
- Add contribution, conduct, security, privacy, governance, and release documents.
- Label the project pre-alpha and restrict production use.
- Create public roadmap and issue labels.
- Add CI for schemas, policies, tests, linting, dependency and security checks.
- Publish a threat model and supported-version policy.
- Prepare a demo using synthetic, clearly labelled data.
- Define release cadence and deprecation policy.
- Recruit domain, privacy, security, data, and marketing maintainers.

## Recommended initial issue labels

`good first issue`, `help wanted`, `security`, `privacy`, `governance`, `workflow`, `connector`, `schema`, `evaluation`, `documentation`, `breaking change`, `blocked`, `MVP`.
